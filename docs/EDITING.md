# Как менять оформление, не затрагивая физику

Программа разделена на небольшие файлы по назначению. Для изменения внешнего вида достаточно обычных знаний Python: переменные, словари, функции и классы. Веб-технологии и системы сборки интерфейсов не используются.

## Сначала запустите исходники

1. Установите Python 3.11+ с Tkinter.
2. Откройте папку проекта в редакторе, например IDLE, VS Code или PyCharm.
3. Установите Pillow: `python -m pip install -r requirements.txt`.
4. Выполните `python main.py`.
5. Изменяйте один небольшой участок, сохраняйте файл и перезапускайте программу.

Упакованная папка предназначена для показа. Редактировать нужно `.py`-файлы в исходном проекте, а затем при необходимости заново собрать приложение.

## Где искать нужную настройку

| Что изменить | Где смотреть |
|---|---|
| Цвета линий, фона, сетки и надписей | `stochlab/appearance.py` |
| Размеры и шрифты оформления | `stochlab/appearance.py`, затем место использования настройки в `stochlab/app.py` |
| Русский или английский текст кнопки | `stochlab/texts.py` |
| Порядок кнопок и полей в панели | `stochlab/app.py` |
| Толщину, расположение осей и условные обозначения | `stochlab/plotting.py` |
| Текст теории и сведения об авторах | `stochlab/texts.py` и создание соответствующей страницы в `stochlab/app.py` |
| Логотип | `assets/vmk-logo.png`; путь упаковки находится в `stochastic_resonance.spec` |

Файл `stochlab/model.py` содержит уравнения движения, ограничения физических параметров, случайные числа и интегратор. Для изменения цветов, размеров, надписей или расположения панелей его править не нужно.

## Цветовые схемы

В `appearance.py` находятся готовые схемы. Обычный цвет задаётся строкой вида `"#245b86"`: это шестнадцатеричная запись красного, зелёного и синего компонентов. Например, `"#000000"` — чёрный, `"#ffffff"` — белый.

При изменении схемы сохраняйте названия её полей: код графиков обращается к ним. Меняйте значения цветов, а не структуру объекта. Не удаляйте существующие схемы до проверки меню в обоих языках.

В режиме «По величинам» цвет объясняет, какая величина нарисована: координата или внешняя сила. В режиме «По сторонам барьера» цвет координаты дополнительно показывает сторону потенциальной ямы. В чёрно-белом режиме информация сохраняется без цвета: внешняя сила имеет пунктирную линию, координата — сплошную. При добавлении новых цветов обязательно проверяйте и печатную версию.

Рисование и экспорт используют одинаковое описание графики. Поэтому изменение цветов или толщины в сцене переносится в SVG, а не существует только на экране.

## Прокручиваемая панель

Панель параметров находится в собственном контейнере с вертикальной прокруткой. Графики расположены в соседнем контейнере. Чтобы сохранить это поведение, добавляйте новые поля внутрь панели параметров, а не в общее окно.

Если добавляете элемент, проверьте:

- до него можно добраться колесом мыши или полосой прокрутки;
- прокрутка панели не сдвигает графики;
- действие клавиатурой остаётся доступным;
- на небольшом экране кнопки не обрезаются.

## Изменение надписей

Переводы собраны в `texts.py`. Найдите существующую надпись поиском в редакторе. При изменении смысла исправьте русский и английский варианты. Если добавляете новое обозначение, передавайте его в виджет тем же способом, что соседние надписи, вместо размещения перевода внутри обработчика физики.

Не меняйте внутренние идентификаторы параметров `T`, `a`, `b`, `f`, `omega`, `gamma`, `seed` только ради переименования подписи. Внешний текст и имена параметров — разные вещи.

## Проверка после правки

Запустите программу и проверьте главную страницу, демонстрацию, теорию и авторов на обоих языках. Для изменения оформления особенно полезны такие действия:

1. Откройте демонстрацию и прокрутите панель до конца.
2. Запустите движение, поставьте на паузу и переключите цветовые схемы.
3. Поверните график, проверьте подписи и соответствие цветов легенде.
4. Сохраните SVG и откройте его в браузере или редакторе векторной графики.
5. Выберите чёрно-белую схему и убедитесь, что линии различаются.
6. Уменьшите окно и проверьте, что все настройки доступны.

Общие проверки кода запускаются командой:

```sh
python -m unittest discover -s tests -v
```

Тесты интерфейса требуют графического сеанса; в CI они выполняются на виртуальном экране Linux и в Windows. Тесты модели не требуют запуска окна.

## Когда нужна новая сборка

После изменения исходников упакованное приложение не меняется само. Повторите команды из README или отправьте изменения в pull request и скачайте новый успешный артефакт GitHub Actions. Архив должен содержать всю папку приложения вместе с `_internal`.


## Сглаживание графиков

`GRAPH_SUPERSAMPLING` в `appearance.py` — во сколько раз больше экранного размера строится вспомогательный кадр. Значение 2 подходит для обычного показа; 3 повышает качество, но увеличивает нагрузку. Меняйте только это значение, если нужно сравнить качество и скорость. Приборные данные и CSV при этом не меняются.

`GRAPH_FONT_FILE` задаёт локальный шрифт для подписей; он включается в сборку из `assets/fonts`. В `rendering.py` находится преобразование готовых линий в сглаженный кадр. В `plotting.py` остаются координаты линий и SVG. Не добавляйте усреднение или фильтрацию координаты ради красивого рисунка: это изменило бы наблюдаемые флуктуации.
